# Lessons in Shelter

Звук уроку в навушниках кожної дитини — **без інтернету**, без застосунку і без реєстрації.

Ідея така сама, як у хмарного сервісу OpenedMic, але сервер стоїть тут же, в укритті.
Учитель говорить у петличний мікрофон, звук іде на маленьку коробку (Raspberry Pi або старий
ноутбук), а вона роздає його по шкільній Wi-Fi мережі на телефони дітей. Дитина підключається
до Wi-Fi, відкриває сторінку, натискає «Слухати» — і чує вчителя в навушниках.

```
 🎙️ петличка ──► [ сервер: Pi / ноутбук ] ──► [ Wi-Fi точка доступу ]
                   ffmpeg → MediaMTX            мережа "Ukryttia-279"
                   Opus, ~48 кбіт/с                     │
                                           ┌───────────┼───────────┐
                                          📱🎧         📱🎧        📱🎧
                                   http://10.0.0.1:8080/listen.html?ch=klas-5a
```

Затримка — приблизно 0.2 секунди, тобто голос у навушниках збігається з тим, що дитина чує
в класі. Інтернет не потрібен взагалі: ані серверу, ані телефонам.

## Що потрібно

| Що | Навіщо | Примітка |
|---|---|---|
| Wi-Fi точка доступу | мережа для 30–40 телефонів | домашній роутер часто «провисає» після 20–30 клієнтів; краще точка офісного класу |
| Raspberry Pi 4/5 або старий ноутбук | сервер | ноутбук зручний власним акумулятором |
| USB-звукова карта або USB-петличка | вхід мікрофона | приймач бездротової петлички теж вмикається в USB |
| Павербанк / ДБЖ | живлення при відключеннях | Pi і точку доступу павербанк тягне довго |
| Навушники в дітей | — | кому не вистачило — саджаємо ближче до дошки |

Один голосовий канал — це близько 48 кбіт/с. На 40 дітей виходить менше 2 Мбіт/с, тож
вузьке місце не швидкість, а кількість підключень до точки доступу.

## Швидкий старт

### Windows (ноутбук учителя)

1. Завантажити `mediamtx.exe` і `ffmpeg.exe` у [server/bin/](server/bin/):
   ```powershell
   .\server\win\download-tools.ps1
   ```
2. Дізнатися точну назву мікрофона:
   ```powershell
   .\server\win\list-devices.ps1
   ```
3. Один раз відкрити порти у фаєрволі (PowerShell від імені адміністратора) — без цього
   телефони не побачать сервер:
   ```powershell
   .\server\win\allow-firewall.ps1
   ```
4. Запустити сервер:
   ```powershell
   .\server\win\start-server.ps1
   ```
5. В іншому вікні PowerShell запустити мікрофон:
   ```powershell
   .\server\win\start-mic.ps1 -Device "Мікрофон (USB Audio Device)" -Channel klas-5a
   ```
   Додайте `-Slow`, щоб поруч ішов резервний AAC-потік для iPhone (див. нижче).
6. На телефоні відкрити `http://<IP-ноутбука>:8080/` — IP скрипт показує сам при старті.
   Телефон має бути в тій самій Wi-Fi мережі, що й ноутбук.

### Raspberry Pi (постійна «коробка»)

```bash
./server/linux/install.sh              # один раз, поки ще є інтернет
./server/linux/start-server.sh         # медіасервер + сторінка
./server/linux/start-mic.sh plughw:1,0 klas-5a   # в іншому терміналі
SLOW=1 ./server/linux/start-mic.sh plughw:1,0 klas-5a   # плюс резервний потік для iPhone
```

Щоб усе піднімалось саме при ввімкненні живлення, скопіюйте проєкт у `/opt/lessonsinshelter`
і поставте юніти з [server/linux/systemd/](server/linux/systemd/):

```bash
sudo cp server/linux/systemd/*.service /etc/systemd/system/
sudo systemctl enable --now lessons-server lessons-web lessons-mic@klas-5a
```

## Класи і канали

Список класів редагується в [web/channels.json](web/channels.json). Кожен запис — окремий
канал зі своїм мікрофоном, тож в одному укритті можуть одночасно йти кілька уроків:

```json
{ "id": "klas-5a", "name": "5-А", "room": "Сектор 1", "color": "#e0b341" }
```

Для кожного каналу запускається свій `start-mic` з власним мікрофоном.

## Як це влаштовано

- **MediaMTX** ([конфіг](server/mediamtx.yml)) — готовий медіасервер одним файлом. Приймає
  звук по RTSP і віддає браузерам по WebRTC.
- **ffmpeg** знімає звук з мікрофона, чистить його (зріз низів, компресор, лімітер) і кодує
  в Opus — кодек, зроблений саме для голосу.
- **Порти**, які мають бути доступні телефонам: `8080` (сторінка), `8889/tcp` і `8189/udp`
  (WebRTC), `8888` (резервний HLS). `8554` (RTSP) потрібен лише всередині сервера.
- **Сторінка для дітей** ([web/](web/)) написана на чистому HTML, CSS і JS. Ніяких CDN,
  Tailwind чи Google Fonts: усе, що вантажиться ззовні, в укритті без інтернету просто не
  завантажиться. [web/whep.js](web/whep.js) — свій маленький WHEP-клієнт на 100 рядків.

## Що вже перевірено

На машині розробки прогнано весь тракт, окрім самого браузера:

- MediaMTX v1.9.3 піднімається з [server/mediamtx.yml](server/mediamtx.yml) — RTSP :8554,
  HLS :8888, WebRTC :8889;
- ffmpeg публікує Opus-потік, сервер його приймає, і зворотне читання показує реальний звук;
- WHEP-адреса `/<канал>/whep` відповідає, резервний HLS-потік `-slow` віддає плейлист;
- сторінка для дітей і `channels.json` роздаються вебсервером.

Не перевірено наживо: відтворення в реальному браузері телефона (Android та особливо iPhone) —
це перший пункт пілотного тесту.

> Конфіг навмисно не використовує ключі, які в різних версіях MediaMTX називаються по-різному
> (наприклад `rtspTransports` проти старішого `protocols`). Якщо сервер пише
> `json: unknown field ...` — приберіть цей рядок, значення за замовчуванням підходять.

## Важливі нюанси

1. **Мікрофон знімаємо на сервері, а не в браузері вчителя.** Браузери не дають доступ до
   мікрофона на сторінках по HTTP, тільки по HTTPS. Тому петличка вмикається прямо в сервер —
   учителю навіть не потрібен свій телефон.
2. **«Мережа без інтернету».** Android може сам перемкнутися на мобільні дані. Дитині треба
   один раз обрати «Залишатися підключеним» — це написано на сторінці і на аркуші
   [web/print.html](web/print.html), який вішаємо на стіну.
3. **Автовідтворення.** Браузер не увімкне звук без дії користувача, тому в інтерфейсі є
   велика кнопка «Слухати».
4. **Заблокований екран.** На частині телефонів, особливо iPhone, звук може стати після
   блокування екрана. Сторінка просить екран не гасити; надійного обходу по HTTP немає.
5. **iPhone.** Обов'язково перевірте на реальному iPhone до першого уроку: Safari суворіший
   до сторінок без HTTPS. Якщо WebRTC там не піде, працює кнопка «Спробувати повільний режим» —
   резервний HLS-потік із затримкою кілька секунд. Щоб він існував, мікрофон треба запустити
   ключем `-Slow` (Windows) або `SLOW=1` (Linux): тоді той самий ffmpeg публікує додатковий
   AAC-потік `<канал>-slow`, бо Safari не грає Opus у HLS. Медіасервер збирає HLS лише на
   перший запит, тому після натискання кнопки звук з'являється за кілька секунд — сторінка
   сама повторює спроби.
6. **Порт 8080 часто вже зайнятий.** pgAdmin/EnterpriseDB, Jenkins та інші тримають саме його,
   і тоді телефон відкриє чужу сторінку («Server is up and running») замість списку класів.
   `start-server.ps1` перевіряє це при старті й підказує інший порт:
   ```powershell
   .\server\win\allow-firewall.ps1 -WebPort 8081   # від імені адміністратора, один раз
   .\server\win\start-server.ps1  -WebPort 8081
   ```
   Адреса для телефонів тоді `http://<IP>:8081/`. Порти WebRTC і HLS від цього не змінюються.
7. **Autoplay і кілька класів поруч.** Рознесіть канали по кабінетах, інакше дитина може
   випадково слухати сусідній урок — імен класів у списку для цього достатньо.

## План впровадження

1. **Прототип на столі.** Ноутбук, звичайний роутер, 5–10 телефонів. Міряємо затримку,
   перевіряємо Android та iPhone.
2. **Пілот в одному класі.** Окрема точка доступу, аркуш з інструкцією на стіні.
3. **Готова коробка.** Raspberry Pi, який сам стартує від живлення.
4. **Кілька класів одночасно** і опис, який можна передати іншим школам.
